# Blog 2.0 设计

这份文档记录 2.0 重写时已经确定的设计决定。2.0 是完全重写，不沿用旧的代码和样式。

## 定位

一本灵感手账：在一块无限画布上记录技术踩坑和随想。整体参考无边记（Freeform），浅色纸面，手绘风格。

不采用：深色、科技风。

## 内容

有两种内容：

- **踩坑**：技术问题的记录。篇幅较长，经常带代码。
- **随想**：短的想法。

每篇都是 `src/posts` 下的一个 Markdown 或 MDX 文件，frontmatter 如下：

```yaml
---
title: "通过 Cloudflare AI Gateway 使用 LLM"
description: "资源准备、配置和使用示例" # 一句话摘要：显示在卡片上，也用作页面的 meta description
type: 踩坑 # 踩坑 | 随想
topic: AI # 必填，只能一个；决定卡片在画布上属于哪一堆
tags: [AI, LLM, Cloudflare] # 可选，多个；用于搜索和筛选
status: 已解决 # 可选，仅用于解决具体问题的踩坑笔记：已解决 | 未解决；显示为卡片上的戳
related: [some-other-note] # 可选；画布上的连线只来自这里，构建时校验目标存在
source: "https://…" # 可选，翻译或转载的原文链接
pubDate: 2025-10-08
updatedDate: 2025-10-09 # 可选
heroImage: "../assets/…" # 可选；有封面图时卡片上贴一张拍立得
---
```

Schema 定义在 `src/content.config.ts`。当前主题：AI、Web、后端、Go、云原生、运维与网络、早年笔记。文章配图放在 `src/assets/posts/<slug>/`。

- 随想也必须有 `title` 和 `topic`。
- `related` 按双向处理：A 写了 B，B 的抽屉里也会列出 A。

## 页面

| 地址 | 内容 |
| --- | --- |
| `/` | 画布（手机上默认显示列表） |
| `/list` | 按时间排列的列表 |
| `/notes/[slug]/` | 画布，并在抽屉中打开这篇 |
| `/notes/[slug].md` | 文章的 Markdown 原文，给 AI 和纯文本阅读用 |
| `/links/` | 友链：全部名片和「交换友链」 |
| `/rss.xml` | RSS |
| `/llms.txt`、`/llms-full.txt` | 给 AI 读的站点说明和全文 |
| `/admin/` | 审核台：待审评论和贴纸的收件箱，点一条跳到它所在的笔记页或画布上审核；由 Cloudflare Access 保护 |
| `/api/*` | 评论和贴纸接口 |
| 404 | 未找到 |

没有单独的关于页，自我介绍放在画布中央。

## 画布

- **中心**：自我介绍卡。
- **主题堆**：每个 `topic` 是一堆卡片，上方有手写的主题名。
- **排布**：全部自动完成，不手动摆放。
  - 各主题堆围绕中心排成一圈，最近更新的主题离中心最近。
  - 堆内卡片松散排列，每张随机旋转 ±1–2°。
- **卡片样式**：
  - 随想是便利贴，内容短，在画布上就能读完。
  - 踩坑是卡片，显示标题、摘要、标签，角上盖着状态戳。
- **连线**：只画 `related` 声明的关系，用手绘线，可以跨主题。
- **初始视图**：停在中心的自我介绍卡，正常字号，周围的主题堆露出一部分。
- **工具条**：浮在顶部，包含名字、搜索、画布/列表切换。
- **缩放控件**：缩小、放大、回到中心。

### 排布参数（原型已确认）

- 主题堆从中心向外螺旋排开，按最近更新排序，互不重叠。堆与堆之间留 34px。
- 堆内卡片按瀑布流排列：1–2 篇一列或两列，3–4 篇两列，5 篇以上三列；列宽 252px，卡片间距 18px，主题名占 52px 高。
- 卡片随机旋转 ±1.7°、随机偏移几个像素。
- 卡片文字允许任意位置断行；摘要行数上限：索引卡 4 行，便利贴 6 行。

## 抽屉

- 点击卡片后从右侧滑出，同时把地址更新为 `/notes/[slug]`。直接访问这个地址时，会显示画布并打开抽屉。
- 抽屉打开时，画布变暗但仍然可以拖动；点击另一张卡片会直接切换抽屉内容。
- 宽屏（> 820px）抽屉打开时，工具条收在抽屉左边的桌面上（放不下就折行），缩放控件移到桌面右下角，都不被抽屉盖住。窄屏（≤ 820px）抽屉盖住整个桌面，画布、缩放控件和工具条设为 `inert`，Tab 不会走到看不见的地方；关闭抽屉或屏幕变宽时恢复。
- 抽屉打开时，在画布空白处单击（没有拖动）会关闭抽屉。
- **内容**：
  - 顶部：类型 · 主题 · 日期，踩坑还有状态戳。
  - 中间：标题，然后是正文。
  - 底部：
    - 「相关」：双向的 `related`。
    - 「同一主题」：同一堆里的其它笔记。
- **操作**：`Esc` 关闭；上一篇和下一篇在同一主题内切换。

## 列表

- 按年份分组（文章跨 2019–2025 年，按月分组太碎）。
- 每行：类型图标、标题、主题、日期。
- 顶部可以按类型和主题筛选。
- 手机上默认显示这一视图，画布作为可选。

## 友链

- 博主手写维护一份列表（`src/data/links.ts`），每条是名称、网址、一句话介绍，可选头像和交换日期。
- **画布上**：主题堆之后自动排出一个「友链」角落，像一叠贴在桌上的手写名片：最多 6 张，两列，每张用纸胶带贴住、微微歪着；左边是头像（放在手绘圆圈里），没有头像就是手写的名字首字，墨水色按名字取；下面是网站地址和一句话介绍，交换日期盖成蓝色日期戳。点名片在新标签页打开对方的网站。标题「友链」和末尾的「全部友链 →」去 `/links/`（普通页面，不开抽屉）。
- **还没有友链时**：这个角落只有一张便利贴「交换友链」：在任意笔记下留言，或到 GitHub 找我；下面是本站的名片（名称 Sonui 的手账、地址、一句话介绍、头像地址），每项有「复制」按钮，复制后旁边写「已复制」（屏幕阅读器也会读出来）。
- **`/links/`**：桌面上一张写着「友链」的纸，下面是全部名片，最后是「交换友链」便利贴和页脚。列表视图（`/list/` 和手机上的列表）在年份之后有「友链」一节：所有名字，加一个去 `/links/` 的链接。
- 动效只有名片悬停时被拿起一点（和卡片一样），入场和其它卡片一起落下；减弱动效时都没有。头像存在本站，不外链。

## 版权

- 文章署名 Sonui，采用 CC BY-NC-SA 4.0（署名-非商业性使用-相同方式共享）。
- **版权纸条**：每篇笔记正文之后、「相关」之前，一张虚线边的小纸条，右上角盖一个朱红「版权」小戳：作者、原文链接（带「复制」按钮，复制后写「已复制」）、发布于 / 更新于、协议（链接到中文协议说明），最后一行「转载请署名并注明原文链接，非商业使用，改编后以相同协议发布」。
- **页脚**：一行淡铅笔小字「© 最早一篇笔记的年份–今年 Sonui · 文章采用 CC BY-NC-SA 4.0」，加「隐私说明」「开源许可」和「RSS」。放在画布的自我介绍卡底部（卡上已经有 RSS，只加隐私说明和开源许可）、列表底部、`/links/`、`/privacy/`、`/licenses/`、404。年份在构建时算。
- 备案号暂不显示；配置里留了一个空字段，以后填上就会出现在页脚。
- 机器也能读到：文章的结构化数据写明协议和版权人，RSS 有版权声明，`llms.txt` 和每篇的 `.md` 版本写明协议。

### 开源许可

- 本站源码采用 MIT（仓库根目录 `LICENSE`，Copyright (c) 2025-2026 Sonui，保留署名即可使用）；`LICENSE` 末尾写明 MIT 只管源码，`src/posts/` 的文章和配图仍是 CC BY-NC-SA 4.0，第三方素材按各自许可。
- **`/licenses/`「开源许可」**：和 `/privacy/` 一样的一张纸。开头两行本站自己的许可，然后分组列出用到的别人的东西（浏览器里运行的代码 / 字体 / 模型 / 素材 / 构建工具）：名称、版本、许可证小戳（点了跳到全文）、用在哪、版权行、许可证文件链接；最后是 MIT、Apache-2.0、SIL OFL 1.1 全文各一份，收在 `<details>` 里。从别处链到某一项（如 `#u2netp`）时这一项涂上荧光笔。打包压缩会去掉库的版权声明，所以声明都放在这页。
- 清单在 `src/data/licenses.ts`，npm 包的版本构建时从 `node_modules` 读；加库、字体、模型、素材时先改它，再改 `ATTRIBUTIONS.md`。贴纸工坊「自动抠图」的说明里链到 `#u2netp`（新标签页打开，不丢正在做的贴纸）。
- 切片后的小赖和朱雀仿宋保留了版权行、丢了许可字段，所以 `public/fonts/{xiaolai,zhuque}/OFL.txt` 放原版权行加 OFL 全文，`bun run fonts` 每次重写。

## 视觉

- 手绘程度：像手账或速写本。有纸张纹理，卡片用胶带贴住，线条像铅笔或钢笔画的。
- 纸色：
  - 背景：米黄 `#eee2c6`，带点阵纹理（20px 间距）。
  - 文档：浅米 `#f6edd6`。
- 背景（画布）和文档要用不同颜色区分开。文档包括踩坑卡片和抽屉里的正文，用更浅的纸色，加阴影浮在背景上。点阵、方格这类纹理只画在背景上。
- 不采用：软木板、照片墙。
- 配色：颜色都取自文具，不用 IDE 或 UI 风格的彩色。
  - 便利贴：统一一种淡黄 `#fbe7a1`，不按主题或类型分色。主题靠画布上的位置和手写主题名区分；主题会越来越多，按颜色分迟早不够用。
  - 墨水：正文 `#2d2822`，铅笔灰 `#524a3e` 用于次要文字和批注。元信息（日期、主题、标签、计数）和占位符用淡铅笔 `#574f43`。更浅的 `#9d917a` 只用于项目符号、图标这类非文字的记号；输入框下划线和搜索框边框用 `--field-line`（`rgb(94 78 52 / 0.75)`，各纸色上 ≥ 3.5:1）。
  - 链接：蓝黑墨水 `#3d5f8f`。
  - 状态戳：印泥 `--stamp`（`#bf3f36`）只画边线和记号；戳上的字、报错等朱红文字用更深的 `--stamp-ink`（`#9e3129`）。「已解决」不透明，斑驳感只靠斑点遮罩；「未解决」用铅笔灰字，虚线边框淡一些，看起来没盖实。
  - 日期戳：蓝色 `#3d5f8f`，数字不透明，只让边框变淡。
  - 牛皮纸上的字用 `#2a1f12`：牛皮纸纹理很深，正文墨色在上面也只有 4.4:1。
- 对比度（WCAG AA）：按**实际渲染出的纸色**量，不按 token。纸纹是用 multiply 叠在 token 色上的，实际更深；抽屉打开时画布还会盖一层 6% 的暗色。量的方法：取纹理图的平均色和 2% 分位色，乘上 token 色，再叠暗色。
  - 实测纸色：画布 `rgb(220 199 157)`（暗处 `rgb(214 194 152)`），抽屉打开后 `rgb(211 190 149)`；卡片和抽屉 `rgb(241 229 197)`，抽屉打开后画布上的卡片 `rgb(231 218 186)`；牛皮纸 `rgb(165 135 104)`。
  - 文字 ≥ 4.5:1：铅笔灰在变暗的画布上 4.8:1（暗处 4.6:1），在卡片上 6.9:1；淡铅笔只用在纸（卡片、抽屉、列表、工具条、纸条）上，最低 5.6:1；朱红字在变暗的卡片上 5.2:1；日期戳蓝在变暗的卡片上 4.7:1。
  - 非文字 ≥ 3:1：输入框下划线、搜索框边框。
  - 搜索时没命中的卡片淡到 40%，同时移出 Tab 顺序；列表里没命中的行淡到 40%。
  - 抽屉打开时画布变暗只到 6%：再暗，画布上的铅笔字和卡片上的链接就不到 4.5:1。
  - 图表：Mermaid 画成手绘风（mermaid 的 handDrawn 样式，固定随机种子，每次构建一样），墨色线框和小赖字直接画在文档纸上，节点不填色，不贴纸条也不贴胶带；比页面宽的图最多缩到原来的 3/4，再宽就左右滚动。图下有「图的文字版」可以展开看源码。图在写作时预先渲染成 SVG（`bun run diagrams`），页面不加载 mermaid。
  - 代码高亮只用几种墨水色：关键字蓝黑 `#3d5f8f`、字符串赭石 `#9a4d2c`、注释灰 `#736b59`（原来的 `#8f8672` 在纸条上对比度只有 3.5:1，加深到 4.5:1 以上）。
- 字体（不用霞鹜文楷）：

  | 用途 | 字体 | 授权 |
  | --- | --- | --- |
  | 主题名、便利贴、批注 | 小赖字体 Xiaolai，英文和数字用它自带的字形 | OFL 1.1 |
  | 正文 | 朱雀仿宋 Zhuque Fangsong | OFL 1.1 |
  | 代码 | Maple Mono，默认关闭连字（`font-feature-settings: "calt" 0`），待确认 | OFL 1.1 |

  - 小赖字体原文件约 21 MB，朱雀仿宋约 8 MB，上线前要用 cn-font-split 切片按需加载。npm 上现成的 `@chinese-fonts/*` 切片版本过旧，要从最新的发布文件自己切。
  - 朱雀仿宋目前是技术预览版，正式版发布后替换文件即可。作者要求 1.0 之前不要传播修改过的版本；切片只用于本站加载，不单独分发。

## 手账组件（原型中，待确认）

素材都要是可免费商用的真实素材或原创绘制，不用 CSS 噪点去模拟材质。

- 纸张：画布和文档都叠一层真实纸纹（ambientCG Paper001 派生，CC0）。
- 踩坑卡：横线索引卡，左侧一条红色页边线；用纸胶带或回形针固定；角上是带斑驳墨迹的「已解决 / 未解决」戳；右下角是蓝色日期戳。有封面图的笔记在卡片上贴一张拍立得。
- 随想：便利贴，不贴胶带，右下角微微翘起。
- 自我介绍卡：贴一条纸胶带，写「这本手账属于」。从它画一个手绘箭头指向最近更新的主题，旁边写「最近在折腾」。
- 贴纸：Codex 生成的原创贴纸，共 16 张，分地方、人物、开发小物三类。其中一张是头像里那只戴眼镜、戴耳机的狗。主题堆旁各放一两张，画布外圈放地方和人物贴纸，抽屉页眉放一张主题贴纸。
- 抽屉：顶部贴一条网格纸胶带；页眉是手账格式（No.、日期和星期、主题）；左侧红色页边线；小节标题带手写圈号；清单用手绘勾选框；代码块是用胶带贴上去的纸条，右上角是牛皮纸文件名标签；页边可以贴便利贴写旁注；用 Rough Notation（MIT）画荧光笔、下划线和方框；底部的「相关」和「同一主题」做成牛皮纸吊牌。
- 素材来源：ambientCG（CC0）、Openclipart（公共领域）、Doodle Icons（CC0）；纸胶带用 CC0 纸纹自行渲染。

## 动效原则

重点不是特效，而是恰到好处、让人觉得舒服的反馈。

- 每个动效都要有来由：模拟纸、胶带、笔这些真实材料的行为，不做和材料无关的炫技。
- 细节可以抠得很细，但整体安静；只在加载和交互时出现，不做持续循环的背景动画。
- 尊重 `prefers-reduced-motion`。
- 时长和曲线：一般动作 150–350ms，统一用 ease-out 类曲线；抽屉用几乎察觉不到回弹的弹簧。

动效清单（已确认，参数以原型为准）：

1. 初次进入：卡片像纸片一样落到画布上，阴影由大收小，从中心向外依次出现，总时长不超过 0.6s；主题名下面的铅笔线同时画出。
2. 拖动和缩放：松手后画布带惯性滑一小段再停下；缩放以指针位置为中心。
3. 悬停卡片：卡片被「拿起」，抬高、阴影变大、歪着的角度摆正一些；它的 `related` 连线加深。其它时候连线保持淡色、不动。
4. 搜索：不匹配的卡片变淡，镜头平滑移到第一个结果。
5. 打开抽屉：从右侧滑出，画布稍微变暗；镜头平移，让被点的卡片留在抽屉左侧可见区域。
6. 切换笔记：抽屉不动，正文淡出再淡入。
7. ~~盖戳动画~~：已取消。「已解决」戳保持静态。
8. 画布和列表切换：淡入淡出。
9. 减弱动效时：以上全部直接切换。

## 图片查看

- 抽屉正文里的图片可以点击查看大图：图片从原位置放大到屏幕中央（FLIP 动画，约 320ms），外框是拍立得白边加纸胶带，底部手写图片说明（取 alt）。
- 点背景、按 `Esc` 或点「×」关闭，图片缩回原位置，焦点回到原图。图片可用 Tab 选中、回车打开。
- 减弱动效时直接显示和关闭，不做缩放动画。

## 访客互动

两种访客内容都要先证明是人（填昵称的访客过人机验证，用 GitHub 登录的访客靠登录），再进入待审队列，审核通过后才公开。提交人自己能看到「审核中」。

- **贴纸**：访客上传一张贴纸图片，拖到画布上的某个位置后提交。审核通过后，所有人都能在画布的这个位置看到它。
- **挪贴纸**，三条规则：
  1. **上传者可以挪自己的贴纸**，挪完所有人都看到新位置，不用重新审核。点一下自己的贴纸，出现和摆放时一样的旋转圆点、缩放方块（也能用滚轮、双指和键盘）；拖动就是挪，松手保存，旁边用手写小字提示「已挪好」或「没挪成功，稍后再试」（失败时贴纸回到原处）；按 Esc 或点别处取消选中。鼠标移到自己的贴纸上会出现虚线框和「你的贴纸，可以挪动」。没登录时靠浏览器里记的编辑口令认人，换了浏览器或清了数据就挪不了；登录 GitHub 后贴的贴纸记在账号上，换设备登录也能挪。
  2. **博主可以挪任何访客贴纸**：工具条上的「整理贴纸」只对博主显示：用 GitHub 登录的博主直接显示；没登录时，在这个浏览器打开过 `/admin/`（或从审核台的卡片点进来）才会去确认 Access 身份，访客不会多一次请求。打开后访客贴纸都能挪，保存给所有人。手账自带的贴纸是代码的一部分，这里挪了也只留在自己的浏览器里。
  3. **每个人都能只为自己挪贴纸**：画布上所有贴纸（访客贴纸、主题贴纸、小狗、外圈的地方贴纸）都能拖开，只记在自己的浏览器里，别人看不到；只能拖，不能转和缩放。拖过之后工具条出现「贴纸放回原位」，点一下贴纸滑回原位（减弱动效时直接回去）。
  - 按住贴纸拖的是贴纸，不是画布；移动不到 4px 算点击。
  - **撕下来、贴回去**：拖动任何贴纸（自己的、整理贴纸时的、待审的、只为自己拖的）都要先把它**完全撕下来才能移动**。按住往外拉，贴纸留在原处不动，只是顺着拉的方向从后边卷起来，卷起的那条边跟着指针走（拉回来就卷回去）；卷到整张都离开纸面，它才离开桌面、从这时起跟着指针走。
    - 撕下来的那一刻画面不跳：捏着的那条边一直在指针下，卷角在约 340ms 里柔和地（不回弹）松开到一个小卷角，贴纸从捏着的地方垂荡下来，影子同时升起、落得更远；卷的方向先保持拉的方向，再慢慢（约 280ms 的时间常数，走近的那边）转到从捏住的角往里卷。
    - 没撕下来就松手：卷起的部分平平地贴回原处（约 220ms），位置不变，不保存，也不出现垃圾桶。
    - 撕下来以后松手：捏着的边不动，卷角摊平落在松手的地方，轻轻压一下落回纸面，照原来的规则保存。撕下来的贴纸可以一直换地方再贴。
    - 移动不到 4px 仍算点击（选中）；旋转圆点、缩放方块、滚轮和键盘照旧直接生效，不用先撕。
    - 没有 WebGL 或打开「减弱动效」时：拉得比贴纸长边的六成还远就算撕下来；在那之前只是按住的角微微翘起（减弱动效时连这点也没有），撕下来后才抬起，并在约 200ms 里从原处滑到手上（不瞬移；减弱动效时直接到位）。
    - 卷纸效果（WebGL）单独加载：指针移到贴纸上、聚焦贴纸，或画布显示着贴纸且浏览器空闲时就先取回来，第一次撕也能用上；手机列表视图和减弱动效时不取。
    - 屏幕阅读器和键盘用户不受影响，也不多播报什么。
  - **垃圾桶**：一张自己能删的贴纸被完全撕下来之后，右下角（缩放按钮上方）才出现一个手绘垃圾桶；拖到上面桶盖打开，松手贴纸揉成一团掉进去。能删的：上传者自己的贴纸（编辑口令或 GitHub 账号），博主（GitHub 登录的博主直接删；有审核身份时按「拒绝」处理，已公开的就是撤下）。访客拖别人的贴纸只有撕和贴，看不到垃圾桶。
  - **不弹确认**：扔掉后底部出现手写的「已扔掉 · 撤销」，约 5 秒后才真正删除（离开页面时立即发出）；点「撤销」贴纸回到撕下来之前的位置。选中能删的贴纸时按 Delete / Backspace 也是扔掉。审核小卡上没有「拒绝」「撤下」按钮，只写「不要就拖进垃圾桶（或按 Delete）」。
  - **手账自带的贴纸也能扔（只有博主）**：博主（有审核身份，或 GitHub 登录的博主）撕下小狗、主题贴纸或外圈贴纸时同样出现垃圾桶，扔进去和访客贴纸一样卷着掉进桶里、「已扔掉 · 撤销」，约 5 秒后才发出；之后**所有访客**都看不到这张贴纸（它原来占的地方空着，卡片不挪位；别人最多晚 5 分钟看到）。它不删，只是藏起来：审核台的「藏起来的自带贴纸」列出缩略图，点「恢复」回到画布。对博主来说自带贴纸能用 Tab 聚焦，按 Delete / Backspace 同样扔掉，焦点落到「撤销」上。访客完全不变：没有垃圾桶，自带贴纸不能聚焦，也不多发请求。浏览器会记住上次看到的藏起来的名单，加载时先藏好，不会闪一下。
  - 减弱动效时：不翘角、不揉团，只是淡出或直接切换。
- **评论**：自建，不用 Giscus。每篇文章的抽屉底部有评论区，样式按手账风格设计。访客填昵称即可评论，邮箱和网址可选，邮箱不公开。
  - 每条评论是一张小纸条，头像是手绘圆圈里写昵称首字，墨水色按昵称区分；日期用蓝色日期戳。评论者的网址链接加 `rel="nofollow ugc"`。
  - 博主回复是贴在评论下方的便利贴，头像用小狗贴纸。
  - 表单是带红色页边线的卡片：下划线输入框、横线纸留言框（800 字）、Turnstile、红色「寄出」印章按钮。
  - 自己提交的评论在审核通过前以虚线框显示，带「审核中」标记，只有自己能看到。
- **划线评论**：选中正文里的一段文字（同一段内，2–200 字）即可对这段话评论，和普通评论走同一套审核。
  - 被评论的文字下方是铅笔波浪线，旁边的数字是条数。
  - 每组划线评论显示为贴在抽屉左侧桌面上的小便签，与划线同高；一道铅笔笔迹从该行左侧页边的墨点连到便签。便签显示第一条评论，多条时写「还有 N 条」，点击展开全部并可回复。滚动时便签跟随，划线滚出视野时便签隐藏。
  - 抽屉左侧空间不足（小于约 230px，例如手机）时不显示便签，改为点击波浪线弹出。
  - 定位方式：保存划线原文和它前面约 12 个字，文章小修改后仍能重新找到位置；找不到时只在底部评论列表中显示（带原文引用）。
  - 底部评论列表也会列出划线评论，并引用被划的原文，点击引用跳回正文位置。
- **GitHub 登录（可选）**：给想留下身份的访客一个更省事的入口，不是门槛。
  - 不登录照样能评论、划线评论、贴贴纸：填昵称，过人机验证，和以前一样。
  - 评论表单、划线评论的小窗、贴纸的摆放面板上方有一行：「用 GitHub 登录」，旁边小字「或者直接填昵称」。登录后这一行变成「以 <用户名> 的身份留言 · 退出」，昵称、网址输入框和人机验证的状态行都不显示，登录本身已经说明是人。
  - 登录后的评论：头像换成 GitHub 头像（仍放在手绘圆圈里），名字是 GitHub 名字，点名字打开对方的 GitHub 主页（`rel="nofollow ugc"`）。匿名评论保持手写首字头像。
  - 登录的访客拥有自己的评论和贴纸：换一台设备登录，也能看到自己待审的评论和贴纸（「审核中」），也能挪自己的贴纸。
  - 博主（GitHub `sosyz`，按数字 id 认）登录后：自己的评论带朱红「博主」小戳；画布工具条出现「整理贴纸」，不用先打开 `/admin/`。审核和回复（审核台和页面上的审核工具）仍然只认 Cloudflare Access，GitHub 登录的博主能挪贴纸，不能审核。
  - **审核不变**：所有评论和贴纸都先审核，登录的访客、博主自己也一样。
  - 工具条上登录后显示一个小头像，点开是「以 <用户名> 的身份登录」和「退出登录」；没登录时不显示（入口在表单上，不打扰只看笔记的人）。
  - 只读公开资料（`read:user`），不要邮箱，GitHub 令牌读完资料就丢。存了什么、怎么删除写在 `/privacy/`，评论区和列表页有链接。
- **人机验证的样式**：Turnstile 使用 `appearance: "interaction-only"`，平时不显示 Cloudflare 的验证框。提交按钮旁用一行手写小字显示状态：「正在确认你不是机器人……」（铅笔图标轻晃）→「已确认」（蓝色手绘勾）；失败时显示红色「验证没通过，点这里重试」。只有 Cloudflare 要求交互时才显示验证框，外面套一层虚线纸边框。

### 审核

审核插口：评论和贴纸共用一个「审核器」接口，输入待审内容，输出「通过」「拒绝」或「待人工审核」。先实现「全部交给人工」；以后可以增加 AI 审核实现，调用方不用改。

人工审核在内容所在的地方做：评论在它的笔记页上看（划线评论能看到划的是哪句），贴纸在画布上它要贴的位置看。`/admin/` 只是收件箱。

- **审核台 `/admin/`**：页眉写「待审评论 N · 待审贴纸 N」，旁边一个大按钮「从第一条开始 →」，跳到最早的一条待审。下面分「待审」（最早的在前，评论和贴纸混排）和「最近通过」两栏，每条是一张纸条：类型（评论 / 划线评论 / 回复 / 贴纸）、笔记标题（贴纸写「画布」）、摘录或贴纸缩略图、名字和 GitHub 用户名、IP 指纹、多久以前；整张纸条是链接「去现场审核 →」。待审纸条上有一个小的「直接拒绝」，给一眼就是垃圾的内容用：点两下才生效（第一下变成「确定拒绝」），贴纸会提醒图片删掉就没法恢复。没有待审时写「都审完了 ✓」。
- **在现场审核**：从审核台点进来的地址带 `?review=`，页面打开到那一条（评论滚到评论区，贴纸把镜头移到它要贴的位置，旁边浮一张审核小卡），手边是「通过」，评论还有「回复」；处理完点「下一条」，直接去下一条待审，不用回审核台。待审的内容仍然只有博主和提交者自己看得到。
- **拒绝和撤下都是扔进垃圾桶**，没有按钮，也不弹确认：把贴纸或评论拖到右下角的手绘垃圾桶上，桶盖打开，松手就揉成一团掉进去；底部出现「已扔掉 · 撤销」，约 5 秒后才真正发出（离开页面时立即发出），点「撤销」原样回来。待审的是拒绝，已公开的是撤下。
  - 贴纸：和上传者扔自己的贴纸一样，先撕下来再拖；选中后按 Delete / Backspace 也行。
  - 评论（评论区的纸条、划线评论小窗里的每一条、只有一条评论的页边便签）：按住纸条的**纸边**拖（头像、留白、印章处，不是文字上），拖过约 6px 才拿起来，所以文字照样能选中复制；页边便签是摘要，按哪儿都能拖。拿起来时手里是一张同样大小、微微倾斜、影子更深的纸条，原处留一个变淡的位置；垃圾桶浮在抽屉上面。没拖到垃圾桶就松手，或按 Esc，纸条飘回原处。键盘：纸条可以用 Tab 选中（点一下纸边也会选中），按 Delete / Backspace 同样扔掉，焦点落到「撤销」上。审核条上写一行小字「拖进垃圾桶即拒绝 / 撤下（或选中后按 Delete）」。访客看不到垃圾桶，纸条也拖不动。
  - 减弱动效时：纸条不倾斜，扔进去只是淡出，飘回是直接回去。
- **处理已经公开的内容**：博主在页面上也能动已有的内容。评论可以撤下（扔进垃圾桶，变成拒绝，公开页面上消失）、恢复（被撤下的回到公开，「已撤下」里的「恢复」按钮）、写或改博主回复（删回复仍是按钮）；贴纸只能撤下（整理贴纸时扔进垃圾桶），撤下就删掉图片，**不能恢复**，只能在「已扔掉 · 撤销」那几秒里撤销。
- **工具条上的「待审 N」**：浏览器里有审核身份时，工具条显示「待审 N」（评论和贴纸加起来），提醒还有多少没审；没有待审时不显示。
- **谁能审核**：只认 Cloudflare Access（本地开发可以跳过）。在这个浏览器打开过 `/admin/`，或从审核台的链接进来，页面才会去问一次身份，普通访客不会多一次请求。GitHub 登录的博主能挪贴纸（「整理贴纸」），但看不到审核工具。

## SEO 与 GEO

- 每篇文章都有独立的静态页面，正文直接写在 HTML 里，不依赖脚本也能读。画布上的每张卡片都是指向文章的真实链接。
- 每页都有 canonical、Open Graph 和 Twitter 卡片；文章页输出 `BlogPosting` 结构化数据（JSON-LD），首页输出 `Person` 和 `WebSite`。
- 提供 `sitemap.xml`、带全文的 RSS、`robots.txt`，以及给 AI 读的 `llms.txt`、`llms-full.txt`，每篇文章另有一个 `.md` 纯文本版本。
- 旧博客的文章链接 301 跳转到新链接，对照表见 `docs/migration.md`。
- 在 Cloudflare 上确认没有拦截 AI 爬虫。

## 技术栈

- Astro 7，页面在构建时生成；接口通过 `@astrojs/cloudflare` 部署到 Cloudflare Workers。
- D1 存评论、贴纸信息、审核队列和 GitHub 登录的会话；R2 存贴纸图片；Turnstile 做人机验证；GitHub OAuth App 提供可选的访客登录；Cloudflare Access 保护后台。都在免费额度内。
- 画布、抽屉等交互用 TypeScript 直接写，不引入 React；页面之间用 Astro 的视图过渡，切换文章时画布保持不动。
