范围：`/Users/sonui/code/blog`（2.0 分支本地构建 + 预览）。六个方向各由一位审计员独立完成，本报告只合并、去重他们的结论，不补充新判断。线上 blog.sonui.cn 仍是旧 Hexo 站，所以凡是依赖 Cloudflare 边缘的结论都要上线后再确认（见第 4 节）。

## 2. 必须先修（上线前）

以下为所有 critical + high 条目，按根因合并。本次没有 critical。

### 2.1 `_redirects` 第 100 条之后的规则被静默丢弃

- 来源：SEO（high）、内容（high）、GEO（medium）。**严重度有分歧**：SEO 和内容评 high，GEO 评 medium（理由是 /blog/* 从未在线上存在过）。
- 位置：`public/_redirects:3-5`；`src/lib/seo/redirects.ts:73-94`；`dist/client/_redirects:101-113`
- 证据：
  - `dist/client/_redirects` 共 111 条，前 3 条是 splat（`/tags/*`、`/categories/*`、`/archives/*`），adapter 把 108 条静态规则追加在其后。
  - Workers 静态资源解析器（`node_modules/miniflare/dist/src/index.js:113390-113451`，`wrangler-dist/cli.js:160265` 常量相同）遇到第一个 splat 后把后续全部算作动态规则，动态规则上限 100，超出部分打印 “Skipping remaining N lines” 后丢弃。本地构建/预览日志里看不到警告。
  - 逐条 curl：第 1–100 条正常，之后全部 404：`/about/`、`/about`、`/archives`、`/blog/css-study-1/`、`/blog/css-study-2/`、`/blog/c-cpp-binary-trees/`、`/blog/development-notes-for-apache-answer-plugin`。共丢 11 行，其中 `/archives/` 仍靠 splat 兜住，所以可观察到的 404 是 10 个。
  - `docs/deploy.md` 第 9 步（:159）要求 `curl $H/about/` 返回 301，这一步会失败；AGENTS.md:162 也写明 /about/ → /。
  - 每新增一篇文章多 2 条 `/blog/<slug>` 规则，截断点继续前移，以后可能吃掉 Hexo 旧文章的 301。
- 当前实际影响：SEO 审计员指出旧站的 `/about/`、`/blog/go-context/` 本来就返回首页（软 404），所以 /about/ 和 /blog/* 从来不是真实公开页面，眼下损失小；问题在于机制本身。
- 修复建议：
  1. 把 3 条 splat 移出 `public/_redirects`，在 `astro:build:done` 钩子里追加到 `dist/client/_redirects` 末尾；或者改由 Worker/middleware 处理这三个前缀，让 `_redirects` 全部是静态规则（静态上限 2000）。
  2. 可选：删除 `redirects.ts` 里 `readPostFiles()` 生成 `/blog/<slug>` 的循环（少 52 条）。**分歧**：SEO 审计员建议这样做；内容审计员认为只删 /blog/* “只是推迟问题”，必须同时调整顺序。
  3. 加一个构建检查/测试：splat 出现在静态规则之前，或第一个 splat 之后规则数超过 100，就失败。
  4. 修好之前不要再加新的重定向（/sitemap.xml、/notes/、旧图片路径等）。

### 2.2 Cloudflare 区域设置决定 AI 爬虫能否访问（上线时配置）

- 来源：GEO（high）。本地无法验证。
- 位置：`docs/deploy.md:136-146`（sonui.cn zone 的 Cloudflare 控制台）
- 证据：Cloudflare 的 AI Crawl Control / “Block AI bots”、managed robots.txt、Content Signals、Bot Fight Mode、pay-per-crawl 默认值可能覆盖站点自己的 robots.txt，或对 GPTBot / ClaudeBot / PerplexityBot 返回 403、402 或质询。
- 修复建议：AI 爬虫策略 Search/Agent/Training 全部 Allow，关闭 “Block AI bots”；关闭 managed robots.txt 和 Content Signals；关闭 pay-per-crawl；确认 Bot Fight Mode 不质询 AI UA；打开 Crawler Hints。具体核对命令见第 4 节。

### 2.3 CJK 字体块占每页约 70% 体积，拖慢移动端 LCP；559 条规则的字体 CSS 阻塞渲染

- 来源：性能（high）
- 位置：`src/layouts/Base.astro:28-29`；`public/fonts/{xiaolai,zhuque}/result.css`；`scripts/build-fonts.ts`
- 证据：
  - 移动端首页 57 个 woff2 = 1.71 MB（Xiaolai 25 块 / 593 KB，Zhuque 31 块 / 1047 KB，Maple Mono 74 KB）；笔记页 61 个 = 1.83 MB；/list/ 41 个 = 1.07 MB。
  - 慢 4G + 4x CPU（h2 + brotli 副本）：首页 LCP 10.1 s，笔记 11.0 s，列表 7.4 s；字体 3.43 s 开始，最后一个 15.0 s 才到；约 60 次字体替换重排，styleLayout 占 1.45–1.66 s。
  - 全站只用到约 1000 个汉字（dist HTML 971、src 999），字体却带 44,871 和 12,883 个码位，分成 374 和 185 个 unicode-range。
  - 两个 result.css 共 341 KB raw / 约 69 KB br，阻塞渲染，节流下 3.2 s 才完成（其它 CSS 1.6 s）。
- 修复建议：构建时按全站字符集（src/posts、.astro/.ts 文案、frontmatter）做子集，每个字族先输出 1–2 个 “site” woff2 作为首个 @font-face（估算 Xiaolai ≈330 KB、Zhuque ≈450 KB，全站共享缓存）；原 cn-font-split 分块作为第二层，unicode-range 排除已覆盖字符，保证访客留言仍能显示。Xiaolai 只用于标题/UI/便签，子集可以更小。result.css 随之缩到几条规则，可内联或非阻塞加载；可选 preload Zhuque 子集。

### 2.4 移动端隐藏的画布仍下载全部字体、图片和 JS

- 来源：性能（high）
- 位置：`src/styles/canvas.css:1038-1047`；`src/components/canvas/Canvas.astro:64,83,111`；`src/components/canvas/Card.astro:65,74`
- 证据：<640 px 时首页用 `visibility:hidden; opacity:0` 隐藏 `.viewport`，仍参与布局。移动端 / 对比 /list/：字体 57 vs 41 块（+640 KB），图片 32 vs 4（+446 KB，含 11 张不可见的贴纸/胶带/回形针），JS 117 vs 26 KB raw（+90 KB）。节流下 32 张图 589 ms 同时开始，与阻塞 CSS 抢带宽，FCP 3.5 s（/list/ 1.8 s）。笔记页在 <820 px 时抽屉盖住画布，同样付出这部分成本（canvas.ts:49）。
- 修复建议：列表视图下对 `.viewport` 用 `display:none` 或 `content-visibility:hidden`；给贴纸/胶带/回形针 `<img>` 加 `loading="lazy" decoding="async"`；`layout.ts:115-116/224-225` 读 offsetWidth/offsetHeight 在跳过渲染的子树里为 0，需要把 relayout/reveal 推迟到切换到画布视图或关闭抽屉时；保留 `<a href>` 卡片在 DOM 中以免影响 SEO；改完用网络日志复查。

### 2.5 <640 px 抽屉打开时，工具栏和整个画布仍在 Tab 顺序里但被抽屉完全盖住（WCAG 2.4.11、2.4.3）

- 来源：无障碍（high）
- 位置：`src/scripts/canvas/canvas.ts`（抽屉开关，约 L446-520）；`src/styles/canvas.css` 的 `@media (max-width: 639px)` 抽屉规则
- 证据：`a11y-obscure.mjs` 在 /notes/k8s-install/ 390x844 和 320x256：前 6 个 Tab 停靠点中 5 个（Sonui 的手账 / 搜索笔记 / 画布 / 列表 / 贴一张贴纸）被 `[data-drawer]` 完全遮挡；抽屉最后一个控件之后 “hidden focus stops: 12/12”，约 40 个此类停靠点。截图 `audit/a11y/note390-search-focus.png`。手机和桌面放大 ≥~225% / 400% 都会触发。
- 修复建议：抽屉打开且 `matchMedia('(max-width: 639px)')` 匹配时，给 `[data-canvas]`（以及 `.toolbar`，或让抽屉从工具栏下方开始）加 `inert`；在 drawer:close 和媒体查询变化时移除。
